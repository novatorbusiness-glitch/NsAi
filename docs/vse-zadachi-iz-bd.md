### P2 · Temperature=0.0 для Директора/Финансиста/Валидатора (детерминизм управления)
- размер: M · тип: AI
- проблема: Temperature не задан по ролям — директор/финансист/валидатор недетерминированы.
- блокер: Исследовано полностью (13.09). У `hermes -z` НЕТ механизма задать temperature ни через CLI-флаг, ни через config.yaml, ни через env var — для основного conversation loop (тот, что реально исполняет `hermes -z`) параметр temperature вообще не пробрасывается в API-запрос. build_anthropic_kwargs() (agent/anthropic_adapter.py, используется agent/transports/anthropic.py -> AnthropicTransport.build_kwargs) НЕ принимает temperature как параметр в принципе — только max_tokens/tools/reasoning_config/tool_choice/is_oauth/context_length/base_url/fast_mode. Поле config.yaml agent.personalities (hermes_cli/personality.py) — это ТОЛЬКО текстовые оверлеи system-промпта (кавайность/пиратство и т.п.), там нет temperature. temperature существует только в двух ДРУГИХ, не-CLI путях: (1) agent/auxiliary_client.py call_llm() / agent/oneshot.py run_oneshot() — внутренние служебные one-shot вызовы (commit-message, title generation), не связанные с hermes -z; (2) agent/moa_loop.py (MOA-режим, `hermes moa`, отдельная подкоманда, не `-z`). Также обнаружено: наша модель claude-sonnet-5 (Anthropic) подпадает под _forbids_sampling_params() — т.е. даже если бы temperature пробрасывался, Anthropic 400-ит любое не-дефолтное значение temperature/top_p/top_k на моделях этого поколения (Opus 4.7+ и новее правило). Так что принудительный temperature=0 для director/financier был бы отклонён API с 400 даже если бы путь для передачи существовал. ИТОГ: технически невозможно зафиксировать temperature=0 для director/financier через `hermes -z` без правки ядра Hermes (claude-code/hermes-agent core) — либо (а) добавить temperature как параметр build_anthropic_kwargs + прокинуть через CLI-флаг в hermes_cli/oneshot.py и AnthropicTransport, либо (б) сменить модель для director/financier на семейство, которое принимает sampling params (Claude 4.6 и старше), и тогда добавить флаг. НЕ реализовано: backend.py run_agent_task() НЕ менялся — не стал добавлять фиктивные 'будь детерминированным' в промпт, т.к. это не является реальным temperature=0 и было бы нечестной имитацией решения. Решение нужно от Ильи: (1) правка core Hermes (добавить CLI флаг --temperature, пробросить в build_anthropic_kwargs, но он будет игнорироваться/400-ить на sonnet-5 anyway из-за _forbids_sampling_params) — трудозатратно и рискованно трогать core; (2) либо принять, что для этого поколения моделей (claude-sonnet-5) temperature=0 в принципе недоступен на уровне API (не только Hermes) — Anthropic сам это блокирует; практический компромисс — снизить недетерминизм не через temperature, а через usaнее строгие промпты/structured output/tool_choice=required там где применимо.
- создана: 13.09.2026
